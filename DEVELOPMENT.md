# Developer A foundation

Use Python 3.12 and install `requirements.txt` in a virtual environment.
Set `DEBUG=true` and a random `SECRET_KEY` in your local shell. Local development
uses SQLite only when DEBUG is explicitly enabled and DATABASE_URL is absent.
Set DATABASE_URL to use Postgres. Staging refuses to start without that URL.

Run `python manage.py migrate`, then `python manage.py runserver`.
Run checks with `python manage.py check` and `python manage.py test`.

## Staging on Render with Neon

1. Create a dedicated Neon staging database. Use its connection URL with TLS
   (`sslmode=require`) as the private Render DATABASE_URL environment variable.
2. After teammate review and merge, connect this repository's main branch to a
   Render Python web service using render.yaml. Do not create a Render database.
3. Supply all four GRADER_* environment variables. Use fake accounts and unique,
   strong passwords, never personal credentials. SECRET_KEY is generated by Render.
4. Build command: `bash build.sh`. Start command:
   `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --access-logfile - --error-logfile -`.
   Build installs dependencies, collects static files, migrates and runs seed.
   This works without a paid pre-deploy command or interactive shell.
5. Verify /health/, /login/, /account/ and POST logout on the deployed URL.
   Test both grader accounts. Put credentials only in the course submission notes.

Seed is transactional and safe to run repeatedly with the same credentials.
It refuses to overwrite an existing user's different password. If intentionally
changing grader credentials, coordinate a separate password reset first.
Demo data for this skeleton consists of the two accounts; product data comes later.

## Developer B integration

Add a separate Django app for A/B data and logic, with its own migrations/tests.
Coordinate changes to config/settings.py and config/urls.py with Developer A.
Use Django's database-backed sessions (already configured). Apply authentication
only to protected views; the A/B page and stats must remain public. Templates
for the A/B page must contain exactly one button with id="abtest". Do not place
grader passwords, database URLs, session secrets or API keys in source files.

## Review handoff

Link the actual PO issue numbers in the PR before merging. Describe AI-produced
configuration, authentication, seed and tests, plus the team's actual review and
changes. Do not claim staging was verified until the deployed checks pass.
